# ADR-0010：错题消灭由自动连对改为用户处置，难点本并入错题本状态机

日期：2026-10-11　任务：T1-08c　状态：已采纳

## 背景

T1-02 记录的 wrong_book 设计为自动消灭：连续答对 N 次 → eliminated（N 业务层定）。用户在 T1-08 拆片共识中改为：重做答对后由前端弹窗处置——**完全移除**（错题本不再出现该题）或**归入难点本**（易错/难点题目集，支撑后续按题目类型的专项提升分析，M3 消费）。自动消灭无法表达「这题我想留着分析」的意图。

## 决策

1. `WrongBookStatus` 扩为 `active | eliminated | hard`（status 列为 TEXT 无库端约束，**零迁移**）：active = 在错题本；hard = 在难点本；eliminated = 已移除（计数保留、答错自动复活为 active——原复活规则不变）。
2. 消灭触发器从「自动连对 N 次」改为用户处置：答对在册 active 题后前端弹窗（移除 → eliminated / 归难点本 → hard / 保持 → 不动），处置动作走独立端点；**每次**答对在册 active 题都提示，忽略 = 保持（自愈，无需「已提示」字段）。答对在册 hard/eliminated 题不提示（难点本由用户手动管理）。
3. 答错任意在册题 → status 回 active、wrongCount++、连对清零（原语义保留）；consecutiveCorrect 列继续维护，供后续分析（自动消灭不再消费它）。

## 后果

- 难点本零新表（wrong_book 状态视图），将来需要独立字段（如难点原因标注）再 ALTER。
- 「完全移除」为软移除：wrongCount/redoCount 计数保留，答错自动回归错题本——与「重复答错复用同一行并累加计数」的既有语义一致。
- reinforce_queue（需加强清单）不受本决策影响，仍按规划推迟 M3（M1 只记 isTimeout 数据）。
