# ADR-0008：视觉提取经拆片子代理与 staging 目录交换执行

日期：2026-10-11　任务：T1-06　状态：已采纳

## 背景

F1-3 视觉提取要求把题目图片内容转为可搜索文本（vision_text），约 3.9 万张图中的题目宿主部分需要「看图」。本仓库可用的视觉算力是 ZCode 视觉子代理（glm-5.3-flash 分工），没有可用的外部视觉 API 端点与密钥；同时管线要求幂等、可无人值守再蒸馏、零凭据纪律（凭据只从环境变量或密钥服务读取）。

## 决策

1. **vision 阶段自身零网络、零凭据、零子进程**。实际「看图」由主会话按 `vision-manifest.json` 的 pending 键分批分派视觉子代理（glm-5.3-flash）执行：子代理读产物目录 `r2/<键>` 工件，把转写文本写入 staging 目录 `vision-in/<键>.txt`；vision 命令吸收 staging 文本、回写 `visionText`、记 manifest。
2. **提取缓存锚定内容寻址键而非导入版本**（承接 ADR-0007）：重新 parse 后 images 重新键化得到相同键，vision 从缓存直接恢复 visionText，再蒸馏免重提取；缓存命中优先于 staging（staging 内容事后变更不影响已缓存文本，防抖动）。方法论变更后的全量重提取 = 手动删除 vision-manifest.json 对应条目（自用规模可接受；管理触发界面属 M3 范围）。
3. **visionText 按题原子回写**：题目的全部题目宿主图片段（题干/选项/解析）都有文本才回写拼接结果，任一段缺文本保持现值——半截提取状态不入库。题组材料图片不提取（questions 表之外无 vision_text 列）。
4. **OpenAI 兼容 API 提取器为后置可选扩展**：未来有端点与密钥时再实现（届时遵守服务端公网 http/https 与 host 校验、凭据走环境变量）；runVisionStage 保持 async 签名预留接入。

## 后果

- 管线不引入任何运行时凭据与网络依赖；提取成本发生在子代理分派时（真实题库按 manifest.pending 分批消化，跨天可续）。
- 提取质量依赖分派时的转写方法论（提示词约定：只转写可见文字、公式转 LaTeX、无文字写空文件），方法论演进靠删缓存条目重提取，不靠改管线代码。
- 空白 staging 文件按「已提取-空」处理并记 warning——子代理对无文字图的诚实输出（空文件）与懒执行（没写文件 → pending）可区分。
