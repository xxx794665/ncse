# 工作流——多模型协作

> 定义 ncse 的开发协作方式：谁干什么、任务怎么拆、文档怎么同步、配额怎么续。规则同 CLAUDE.md，冲突时以 CLAUDE.md 为准并同步修订。

## 1. 模型分工

| 模型 | 职责 | 典型任务 |
|---|---|---|
| **glm-5.3** | 架构设计、后端编写、测试 | API、D1 schema、导入管线文本/图片模块、测试套件、部署脚本 |
| **kimi-k3** | 前端页面设计与整体前端实现 | 设计规范、tokens/组件库、页面与交互、PWA |
| **glm-5.3-flash** | 视觉识别 | 图片题提取、题目截图导入、申论手写识别、批量 AI 解析 |

- 执行时用对应模型的 subagent 分派；主会话负责拆片、汇总、文档同步。
- 任务索引中每个任务标注负责模型。

## 2. 任务拆片

- 粒度标准：**一个子任务一个产出物、一次会话可完成**——避免单次上下文过大导致注意力丢失。
- 临近执行的里程碑才拆到执行粒度；远期任务在索引中保持功能级。
- 拆片产生的子任务进入 docs/任务索引.md，状态实时更新。

## 3. 文档同步（强制）

| 变更 | 必须更新 |
|---|---|
| 功能新增/变更/完成 | docs/功能清单.md |
| 任务状态/进度/下一步 | docs/任务索引.md |
| 新术语、术语含义变化 | CONTEXT.md |
| 难逆决策（架构/边界/取舍） | docs/adr/（编号递增） |
| 配额中断收尾 | docs/任务索引.md（写回进度与下一步） |

## 4. 再蒸馏与再生成

- 所有 AI 生成产物（知识点树、题目打标、AI 解析、视觉提取文本）带**生成版本**（`import_runs` / 打标版本字段）。
- 管线幂等：同版本重跑 = 覆盖；新版本 = 重生成。方法论变更后支持全量再蒸馏与数据清洗。
- 重新生成的功能与接口（管理触发、按范围选择）在 M3 落地。

## 5. 配额与定时任务

- coding plan 有每日限额：触达后**立即写回任务索引并收尾**，不硬闯；触顶不做任何 git 操作（不提交不推送，见 docs/工程规范.md §2）。
- 每天 09:50 定时任务「每天9点50续跑ncse项目」自动续跑：规划阶段推进文档，开发阶段取下一任务；触发时需 ZCode 桌面端在线。
- 整体开发完成：汇报成果并删除定时任务。

## 6. 里程碑推进

M0 设计系统 → M1 行测刷题 MVP → M2 整卷模考 → M3 知识点体系 → M4 申论 → M5 学习计划 → M6 组卷与间隔重复 → 二期（面试/软考/AI 增强）。

**里程碑完成定义**：功能清单中该里程碑功能全部「已完成」+ 测试通过 + 部署验证 + 文档同步。
**总目标节点**：2027 省考（约 2027 年 3 月）前全量可用；M1 越早越好。
