## 2. 既有资产盘点

**Schema（T1-02 已建四表，shared 枚举齐备）**：

- `knowledge_points`：自引用树（parent_id 空 = 根）、挂模块、`code` 模块内唯一（打标幂等导入依据）、sortOrder；子树随父级联删除。
- `question_knowledge`：题目↔知识点多对多，(question, kp) 唯一；`tag_version`（产出该打标的 import_runs 序号）+ `source ∈ official/ai/human_verified`（TagSource 已在 shared）。
- `mastery_stats`：多态目标（target_type ∈ knowledge_point/module + target_id，无外键、写入方保证合法）；totalCount/correctCount/accuracy/avgDurationMs 原始计数。
- `reinforce_queue`：user+question 唯一状态机；`reason ∈ wrong/timeout`（最近一次触发覆盖）、`status ∈ pending/resolved`（答对由业务层置 resolved、可复活）。

**数据基础**：

- 27,362 真题（qid 唯一、kind 全 single_choice、选项全量）；非空 vision_text 6,130 题。
- **本地开发态已全量导入（2026-10-25，本次前置事项完成）**：import.sql 98.9MB 单次 `d1 execute --local` 导入，七项计数与远端逐数一致（questions 27,362 / groups 1,164 / papers 515 / pairs 58,779 / blueprint_modules 12 / 非空 vision 6,130 / import_runs 1）。
- 作答数据源（远端自 2026-10 起真实积累）：`practice_records`（专项：answer/isCorrect/isTimeout/durationMs）+ `mock_answers`（模考：交卷统一判分后含同字段）——掌握度与需加强的输入。
- 注意：本地 R2 态仅 13 个合成对象，本地开发态真实题目图片经 /api/img 会 404——M3 开发主要消费文本/打标/判分数据，影响有限；需要图片联调时用线上环境。

**管线与工程先例（可直接复用的工作流）**：

- 蓝图种子（T2-01b）：版本化数据文件 → 幂等种子 SQL（含孤儿清理）→ 远端轻量执行——知识点树入库可循此例。
- vision 批量提取（ADR-0008/0011）：批次生成器 + staging 交换 + 吸收回写 + 内容寻址缓存 + 跨天分批子代理 + 成本小批实测先行——AI 打标批量执行可整体套用该模式（成本教训已登记：先实测再承诺节奏）。
- wrong_redo 练习模式（T1-10a）：PracticeMode 判别联合扩值 + sessionDisplayName 显示名——reinforce 练习会话直接照此扩第三个值。
- /review 三视图 ARIA tabs（T1-10b）、/stats 模块分布比例条（T1-11b）——前端扩展点现成。

**AI 通道现状（关键约束）**：运行时 AI 代理（ADR-0005 + AI 设置 F4-3）属 M4 未建。M3 的「glm-5.3 生成树草稿 / AI 打标 / AI 解析」**全部走开发期批量活动**（子代理分派 + 产物入库），不依赖运行时通道；这与功能清单措辞一致（「glm-5.3 生成草稿」指协作模型而非运行时模型）。运行时 AI 能力（如产品内 AI 解析按需生成）在 M4 AI 设置就绪后再接。

## 4. 关键设计决策点（草稿建议，待确认）

- **D1 树形态：两级实体（考点+知识点）固定深度**。CONTEXT 术语「模块→考点→知识点」中模块已由 modules 承载，knowledge_points 只建两级：parent_id 空 = 考点、挂考点 = 知识点；代码层校验最大深度 2（schema 自引用不限深，深度约束是业务规则不进库）。预计全库 100–300 节点。
- **D2 树生成与入库：开发期草稿→人工校对→版本化种子入库**。glm-5.3 按模块生成树草稿（输入=模块名+题型构成+真题样本），用户校对定稿；定稿树为**版本化 JSON 数据文件入 Git**——知识点树是自产知识资产而非爬取题库数据，不属 ADR-0004 禁入范围（待 §6-1 确认）；入库走 importer 种子命令（循蓝图先例：幂等 upsert by code + 孤儿清理 + 独立可执行 SQL）。
- **D3 打标执行模型：vision 同款批量管线 + 成本小批实测先行**。批次生成器从 modules/*.json 产物按题分组（输入=题干文本+选项+官方解析+vision_text）→ 分批分派 glm-5.3 子代理输出 qid→知识点 code 映射 → staging → 吸收幂等 upsert（tag_version=打标运行号、source='ai'）→ 跨天分批消化。**先小批实测单题成本再定全量节奏**（vision 教训：成本由内容密度主导、波动 6 倍+）；打标产物属题库衍生物不入 Git（.import-out staging）。
- **D4 掌握度口径：表存原始计数，指标 shared 派生，判分事务内增量更新**。mastery_stats 维持现状原始计数（accuracy/avgDurationMs 是累计口径非加权指标）；「掌握度」= shared 纯函数 `deriveMastery(accuracy, avgDurationMs, 模块蓝图时限)`（建议权重：正确率 0.7 + 用时得分 0.3，用时得分=平均用时相对时限的紧裕度），「需加强」阈值常量（建议 0.6）同放 shared——两端同锚防漂移（DEFAULT_BLUEPRINT 先例）。更新时机：practice 判分与 mock 交卷两处落库事务内 upsert（按题目所属知识点行累加；module 级行**不双写**，由 stats/summary 现算聚合避免漂移）。模考作答计入掌握度（与专项同权重）。
- **D5 需加强清单规则：自动汇入/自动出队，与错题本并存分工**。汇入：判分答错或 isTimeout（**含答对但超时**——超时=不熟练）→ upsert 复用同一行刷 reason；出队：该题重做（任意模式）答对 → resolved；再触发复活 pending（表设计已定，零迁移）。分工：错题本=用户处置状态机（人决定移除/归难点）、需加强队列=全自动（无处置动作）。模考答错/超时同口径汇入（与错题本 D8 联动一致）。练习入口：PracticeMode 扩 `'reinforce'`——按 pending 题目建会话（循 wrong_redo 先例）。
- **D6 AI 解析（F3-5）：定位重估——建议一期缩小或后置**。官方解析已 100% 覆盖，AI 解析唯一增量是「方法论提炼/多角度讲解」类增强，且全量 27,362 题成本高（vision 量级教训）。建议二选一：a) 一期只对**错题/薄弱知识点题目**开发期批量生成（数量小、价值密度高），产物入新表 `question_ai_analysis`（questionId 唯一+版本+内容，不动官方解析列）；b) 整体后置到 M4（AI 设置就绪后运行时按需生成+缓存）。倾向 a。
- **D7 截图导入（F3-6）：一期做自用工具链，产品化后置**。运行时上传通道不存在（M4）——一期形态：截图入目录 → vision-extractor 式子代理提取 → 生成题目 JSON 草稿 → 人工确认 → 经既有管线入库（复用 parse 产物结构与 db 质量门）；产品内「拍照上传」入口待 M4 AI 通道。也可整片后置（待 §6-6）。
- **D8 前端落点：扩展现有页面，不新增顶级路由**。掌握度：/stats 模块分布卡下钻知识点（点击展开该模块知识点掌握度列表）；需加强：/review 第四视图 Tab「需加强」（pending 列表 + 「强化练习」按钮建 reinforce 会话跳作答页）。树管理界面不做（人工校对是开发期文档流程，非产品功能）。
