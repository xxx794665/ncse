# 架构设计

> 状态：规划定稿（2026-10-07）。实现任务（T1-02 等）落地时可细化；重大变更须新增 ADR 并更新本文。

## 1. 总体拓扑

```
┌─────────────────────────┐          ┌───────────────────────────────┐
│ 前端 SPA（纯静态）        │   HTTPS  │ API（Cloudflare Workers）      │
│ GitHub Pages            │ ───────► │ Hono + Bearer JWT             │
│ tiku.<域名>              │  CORS    │ api.<域名>                     │
└─────────────────────────┘  白名单   └──────────────┬────────────────┘
                                               │
                     ┌─────────────────────────┼─────────────────────┐
                     ▼                         ▼                     ▼
                 D1（SQLite）              R2（对象存储）        外部 AI 服务
                 账号/题库/做题记录          题目图片（压缩后）    OpenAI 兼容
                                                            （账号自带 Key）
```

决策依据：ADR-0003（零成本拓扑）、ADR-0001（React）。

## 2. 技术选型

| 层 | 选择 | 说明 |
|---|---|---|
| 前端 | Vite + React + TypeScript | 纯静态 SPA，无 SSR（GH Pages 限制） |
| PWA | vite-plugin-pwa | 主屏安装、离线兜底 |
| API | Cloudflare Workers + Hono | 免费套餐、TS 原生 |
| ORM | Drizzle ORM（D1） | 类型安全 + 迁移工具链 |
| 数据 | D1 + R2 | 结构化数据 / 题目图片 |
| 认证 | Bearer JWT（localStorage） | 自用规模够用；SaaS 化升级路径：跨子域 httpOnly Cookie + CSRF |
| 包管理 | npm workspaces | apps/ + packages/ + tools/；本机 node v22.20 / npm 10.9，无 pnpm |
| 测试 | Vitest（API/导入管线）；前端关键流程 Playwright（可选） | glm-5.3 负责编写 |
| CI/CD | GitHub Actions | 前端构建→GH Pages；wrangler 部署 Workers |

## 4. 数据模型（T1-02 已定稿：Drizzle schema 见 apps/api/src/db/schema/，七域 27 表 + 首个迁移 migrations/0000；富片段与 M1 枚举同构类型在 packages/shared。关键定稿决策：mastery_stats 多态目标、practice_records.session_id 为 TEXT UUID、mock_sessions 蓝图外键 restrict、打标按自然键 upsert——明细见 docs/任务索引.md T1-02 条目；字段演进走后续迁移）

一切内容挂 `exam_type`（扩容单位，通用层级：考试类型→科目→模块→知识点/题型→题目/蓝图）。

- **账号域**：`users`（预留 role，SaaS 化扩展）；`ai_settings`（OpenAI 兼容 baseURL/Key/模型/参数上限，Key 加密存储）
- **内容域**：`exam_types`、`subjects`（行测/申论）、`modules`（六大模块）；`knowledge_points`（自引用树）；`question_groups`（材料/题组）；`questions`（题干与选项为**富片段**：文本段+图片引用混合；答案、解析、难度、来源元数据 qid/年份/地区/卷型、`vision_text` 视觉提取的可搜索文本）；`question_knowledge`（多对多，带打标版本与来源：官方/AI/人工校对）；`blueprints` + `blueprint_modules`（卷型→模块/题量/时长）
- **练习域**：`practice_records`（逐题作答、判分、用时、**超时标记**、模式）；`mock_sessions`/`mock_answers`（整卷）；`wrong_book`、`favorites`、`notes`
- **复习域**：`mastery_stats`（知识点/模块掌握度）；`reinforce_queue`（需加强清单）
- **申论域**：`essay_materials`、`essay_questions`、`essay_answers`（含手写识别文本）、`ai_grades`、`essay_samples`
- **计划域**：`study_plans`、`checkins`
- **管线域**：`import_runs`（版本、输入摘要、产物统计——幂等与再蒸馏的依据）

## 5. 关键流程

### 认证
注册/登录 → 签发 JWT → 前端 localStorage 存 Bearer → 请求带 `Authorization` 头，CORS 白名单校验。

### AI 代理调用（申论批改/AI 参考答案）
前端 → `POST /api/ai/*` → Workers 读取该账号 `ai_settings`（解密 Key）→ **服务端**发起 OpenAI 兼容请求（仅公网 http/https，先校验 host，拒绝内网/环回）→ 回传结果。申论文本量大，max tokens 取账号设置且默认给大值（8k–16k）。依据：ADR-0005。

### 题库导入管线（幂等、可再蒸馏）
xingcezhenti 仓库 → 文本解析（题组/qid/答案/解析）→ 图片压缩→R2→路径重写 → 图片题视觉提取（glm-5.3-flash 拆片子代理）→ 校验 → D1。每次运行记 `import_runs` 版本；同版本重跑覆盖、新版本重生成，支持方法论变更后的全量再蒸馏与清洗。

入库机制（T1-15 落地）：importer 各阶段产出确定性中间产物——JSON（题目/题组结构化数据）→ upsert SQL（自然键 qid / 题组 module+source_key；import_runs 记运行号与 input_digest 内容指纹；数据质量门默认跳过坏答案题）。SQL 生成至产物目录 `import.sql`，经 `wrangler d1 execute --file` 应用（本地与远端用同一份产物）。文本阶段已可用（图片路径暂为源相对路径，图片阶段完成后重新导入即覆盖重写）。

## 6. 安全与合规（硬约束）

1. 服务端 URL 请求仅允许公网 http/https；请求前校验 host，拒绝 localhost、环回、私有与保留地址。
2. 凭据只从环境变量/密钥服务读取：Workers 用 `wrangler secret`，本地用不入库的 `.dev.vars`；源码、示例、测试不出现可用凭据字面量；JWT 密钥与 Key 加密主钥均为 Workers secret。
3. 题库仅自用（ADR-0004）：不入 Git、不对外分发；GH Pages 仓库公开的代价用「数据不入仓库」规避。

## 7. 部署

- `tiku.<域名>` → GH Pages：GitHub Actions 构建 `apps/web` 发布；仓库需公开
- `api.<域名>` → Workers：wrangler 部署；CORS 白名单仅 `tiku.<域名>`（本地开发另放 `localhost`）
- D1 备份：`wrangler d1 export` 定期导出至 R2 私有目录，保留最近 30 份
- 环境：`dev`（wrangler dev）/ `prod`

## 8. 扩容设计（软考等）

- 内容域全部挂 `exam_type`，按通用层级抽象（面向对象的数据建模），不做代码层插件机制
- 软考接入 = 新增 exam_type + 科目/模块/蓝图配置 + 题库导入，零代码改动为目标

## 9. 前端要点

- React Router 路由全量注册（含占位路由）；功能按 `features/*` 域组织
- TanStack Query 管理 REST 数据；design tokens 用 CSS variables，主题三态持久化
- PWA：App Shell 缓存；题目图片懒加载
