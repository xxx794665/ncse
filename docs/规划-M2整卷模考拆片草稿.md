## 2. 既有资产盘点

- **schema（迁移 0000，远端已应用）**：`mock_sessions`（userId / blueprintId restrict / status / submittedAt）+ `mock_answers`（每会话每题一行、answer 可空可改、isCorrect 交卷判分落值、durationMs / isTimeout）。缺口：无试卷（paper）维度、无题目清单快照、无计时累计字段。
- **蓝图**：`blueprints` / `blueprint_modules` 表已建、**无种子数据**（T1-08 拆片共识④推迟到 T2-01）；shared `XINGCE_BLUEPRINTS` 两条卷型目录 + 推导函数就绪（DEFAULT_BLUEPRINT 已是前后端同锚单一来源，T1-09）。
- **题库**：27,362 题线上（T1-17/T1-18c 收口），含 year/region/paperType 列与 visionText；**无试卷归属列**（独立题在库中不挂任何卷，题组经 source_key 文件路径前缀隐含卷信息）。
- **前端**：/mock 占位页已注册（M2 徽章）；RichContentRenderer 四变体 / QuestionCard / 认证态 / 路由守卫 / 主题三态全部可复用；专项刷题作答页的单题交互与判分反馈模式可参照。

## 3. 数据事实（2026-10-21 探查）

- 按试卷名去重 **515 卷**；全局唯一 qid 27,473（入库 27,362，111 题被 db 质量门跳过）。
- **整卷完整度分层**（按各卷实际归属题量）：

| 实际题量 | 卷数 | 其中六模块齐全 |
|---|---|---|
| ≥120 | 84 | 66 |
| 100–119 | 61 | 50 |
| 80–99 | 48 | 42 |
| 50–79 | 46 | — |
| 30–49 | 38 | — |
| <30 | 238 | — |

- **完整卷候选（非精选、六模块齐全、≥110 题）共 77 卷**：北京历年（135 题）、国考副省级历年（135 题）、上海 A/B 类（130–135 题）、江苏 A 类（135 题）等为主体；近年（2016–2026）每年至少数卷可用。
- **联考同题归因损失（关键约束）**：T1-04 管线「全局 qid 去重保首见并同步清理题组引用」使 **315/505 卷实际题量低于原卷题数**（206 卷损失 ≥100 题、8 卷近乎清空，如 2019 年 420 联考江西卷原卷 135 → 实际 0）。**题目本体都在库中**（qid 全局唯一），只是归属被首见卷独占——多省联考卷在当前数据形态下无法按卷取回完整题集。
- **卷型蓝图 ≠ 真实卷结构**：上海卷（常识 70+、资料个位数）、江苏 A 类（判断 100）等结构与联考标准卷（120 题六模块 15/15/30/10/30/20）差异很大——**整卷模考的题量与时长必须以所选真题卷实际为准**，蓝图仅作每题时限推导的分析锚。
- 源数据 meta 有原卷「题数」但**无考试时长**元数据；qid 为纯数字、卷内不保证连续，真实卷序以产物 items 序（文件内原序）为准。

## 4. 关键设计决策点（草稿建议，待确认）

| # | 决策点 | 建议 | 理由 |
|---|---|---|---|
| D1 | **试卷实体与多卷归属**（ADR-0012 候选）：新增 `papers` 表（自然键 = 试卷源文件名聚合）+ `question_papers` 多对多；推翻 T1-04「去重保首见单归因」，管线重跑（幂等、版本化，符合再蒸馏原则） | 采纳多对多 | 题目实体仍全局唯一（不动），仅归属改多对多；恢复联考卷完整题集是 F2-1「按卷选择」成立的前提；重跑成本可控（parse 2s + db 重生成 + 远端导入 ~1 分钟，T1-17 实测） |
| D2 | **完整卷开放口径**：仅开放 77 卷完整卷候选 vs 全部 515 卷开放并标注完整度 | 全部开放、显式标注（完整/部分 N 题/残卷），仅完整卷默认置顶推荐 | 数据如实呈现，部分卷（如单模块分卷）对「分模块限时自测」也有价值；筛选默认条件给完整卷 |
| D3 | **整卷时长来源**（源数据无时长）：a) 1 题 ≈ 1 分钟默认 + 开考前可调；b) 知名卷型真实时长配置表；c) 每卷手设 | a 起步（向上取整到 5 分钟），b 作为后续增强（常见卷型时长稳定：国考副省 135 题 120 分钟、联考 120 题 120 分钟、北京 135 题 120 分钟） | 零维护起步；真实时长表是少量人工数据，值得做但不阻塞一期 |
| D4 | **判分时机与答案下发**：交卷统一判分（isCorrect 交卷落值，schema 既定注释）；作答中不下发答案/解析 | 沿用专项刷题哲学（T1-08 共识①：服务端判分、答案不随题下发防翻 DOM） | 既有共识直接适用 |
| D5 | **模考超时语义**：作答中不做每题时限告警（F1-6 告警是专项刷题交互）；整卷统一总倒计时；isTimeout 由交卷判分按蓝图每题时限标记，仅供成绩单用时分析 | 采纳 | 模考还原真实考试形态（整卷一表计时）；isTimeout 字段既有用途平滑复用 |
| D6 | **计时口径（中断续考）**：a) 墙钟不暂停（挂后台烧时间）；b) 累计口径（elapsedMs 累计 + 恢复时间戳，中断/切设备不烧时间） | b 累计口径（mock_sessions 增累计字段，前端进入时增量上报） | 模考中断是容错场景（断网/切设备），墙钟会惩罚一次切设备半场作废；与 F1-6 专项墙钟口径的差异属场景差异，可在 ADR-0012 一并记录 |
| D7 | **mock_sessions 结构补齐**：加 `paperId`（restrict，同 blueprint 哲学）+ 题目清单快照 `questionIds`（服务端权威，与 practice_sessions 同哲学） | 采纳 | 会话稳定性：卷内容重导入/再蒸馏不牵连进行中会话与历史成绩 |
| D8 | **模考答错与错题本联动**：交卷判分时答错题是否入错题本（复用 ADR-0010 状态机） | 入（交卷判分批量 upsert，与专项刷题同状态机） | 错题复习闭环不因场景割裂；状态机字段零改动，仅判分路径多一处调用 |
| D9 | **模考作答与 practice_records 关系**：模考作答不写 practice_records（mock_answers 独立承载），/stats 统计口径是否并入模考量后续 M3 一并定 | 不写、暂不并入 | 两表语义不同（append-only 逐题判分 vs 可改答案交卷判分）；避免 mode 枚举膨胀 |
